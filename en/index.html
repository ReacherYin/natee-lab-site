harness × loop engineering

The point isn't which model — it's the layer of engineering around it: giving the agent a reliable frame (the harness) and a loop that converges on its own.

#natee-lab

Harness engineering

Fencing the agent into a reliable frame
  • Hand off with a clear spec and acceptance list; it reports back in a fixed shape — done or not, where it's stuck — so the system reads it without guessing
  • At most two fix rounds, then stop; if it runs long or drops offline, the system knows how to clean up — nothing hangs waiting for a human
  • Every step is safe to re-run — everything done is marked, so no double-dispatch, no double-comment

Loop engineering

Letting the loop converge on its own
  • One issue opens and the whole path — code, review, docs, merge — runs itself; no one babysits
  • When something breaks — failing tests, a dead review, a code conflict, a dropped ticket — the system sweeps periodically and picks it back up
  • Tickets can be ordered "finish that one first" — when the first merges, the next auto-starts
  • Why it's safe to fully automate: every round must pass tests and acceptance criteria, or it doesn't move on
139issues → merged prs, hands-free

Across the whole line, a human shows up in exactly two places: writing the requirement clearly at the start, and nodding it through at the end. Everything in between is the pipeline's.

Almost all of Natee AI Lab is built on it — every FAMS feature, this website itself.
