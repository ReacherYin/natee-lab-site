harness × loop × memory engineering

พองานพัฒนาเข้ามาก็กระจายให้ agents ทันที แล้วอาศัยสถาปัตยกรรมวิศวกรรม AI ทำให้ผลลัพธ์เชื่อถือได้: harness ที่วางใจได้, loop ที่ลู่เข้าหาคำตอบได้เอง, และ long-term memory ที่ยิ่งใช้ยิ่งแม่น

#natee-lab

Harness engineering

ล้อม agent ไว้ในกรอบการทำงานที่เชื่อถือได้
  • ตอนสั่งงาน จะให้ spec และเช็กลิสต์เกณฑ์ตรวจรับที่เขียนไว้ชัด ๆ ส่วนที่มันรายงานกลับมาเป็นรูปแบบตายตัว — เสร็จหรือยัง ติดตรงไหน ระบบอ่านออกเลย ไม่ต้องให้คนเดา
  • ถ้าซ่อมไม่ได้ ให้ซ่อมซ้ำมากสุดสองรอบแล้วหยุด ถ้าทำนานเกินไปหรือหลุดกลางทาง ระบบรู้ว่าต้องเก็บกวาดยังไง ไม่ค้างรอให้คนมาช่วย
  • รันซ้ำได้อย่างปลอดภัยทุกขั้น — สิ่งที่ทำไปแล้วมีเครื่องหมายกำกับ จะไม่สั่งงานซ้ำหรือคอมเมนต์ซ้ำ

Loop engineering

ให้ loop ลู่เข้าหาคำตอบได้เอง
  • เปิด issue ขึ้นมาใบเดียว ตั้งแต่เขียนโค้ด รีวิว เติมเอกสาร ไปจนถึง merge มันเดินจนจบเส้นทางเอง คนไม่ต้องเฝ้า
  • ถ้าเกิดเรื่องกลางทาง — เทสต์พัง รีวิวขาดตอน โค้ดชนกัน ตั๋วตกหล่นไม่ได้ถูกสั่ง — ระบบจะไล่ตรวจเป็นรอบ ๆ แล้วเก็บกลับมาทำต่อเอง
  • ตั๋วแต่ละใบระบุได้ว่า「ทำใบนั้นให้เสร็จก่อน ค่อยทำใบนี้」พอใบก่อนหน้า merge ใบถัดไปก็เริ่มเองอัตโนมัติ
  • เหตุผลที่กล้าปล่อยให้อัตโนมัติเต็มรูปแบบ: ทุกรอบต้องผ่านเทสต์และเกณฑ์ตรวจรับ ถ้าไม่ผ่านก็ไม่เดินต่อ

Memory engineering

ให้ประสบการณ์ค้างอยู่ในระบบ
  • ทำเสร็จแต่ละรอบ agent ต้องบันทึกว่ารอบนี้ทำอะไรไป ตรงไหนต่างจากที่ตกลงไว้ตอนแรก เจอหลุมอะไรบ้าง — spec เขียนไว้ก่อน reality เติมทีหลัง อยู่ในเอกสารฉบับเดียวกัน รอบหน้าที่สั่งงาน มันก็อ่านฉบับนี้
  • เอกสารเชื่อมโยงถึงกัน มี README เป็นสารบัญ ทั้งโฟลเดอร์ docs/ คือ knowledge graph หนึ่งผืน: หาเจอสักฉบับแล้วค่อยไล่ตามลิงก์ขยายต่อ ไม่ต้องยัดทั้งกองเข้า context
  • ก่อนเริ่มฟีเจอร์ใหม่ให้ค้นก่อนว่าเคยทำอะไรคล้ายกันไหม ใช้ซ้ำได้ก็ใช้ซ้ำ แล้วดูด้วยว่าคราวก่อนพลาดตรงไหน — ขั้นนี้ไม่ได้พึ่งการเทียบเวกเตอร์ (RAG) แต่เป็น agent ที่หยิบคีย์เวิร์ดกับสารบัญไปค้นเอง (agentic retrieval) ส่วนการเลือกว่าจะดึงอะไรและใส่เข้า context แค่ไหน นั่นคือ context engineering
  • เอกสารกับโค้ด merge อยู่ใน PR เดียวกัน (atomic) จะไม่มีสถานการณ์แบบ「โค้ดแก้ไปแล้ว เอกสารยังค้างเวอร์ชันเก่า」
139issues → merged prs, hands-free

เวิร์กโฟลว์ซอฟต์แวร์ทั้งเส้นโฟกัสแค่สองเรื่อง: อธิบายความต้องการให้ชัด และตรวจว่าผลลัพธ์ผ่านเกณฑ์ไหม ที่เหลือยกให้ระบบอัตโนมัติทั้งหมด

โปรเจกต์ใน Natee AI Lab แทบทั้งหมดพัฒนาอยู่บนมันทั้งนั้น: ฟีเจอร์ผู้ช่วยของ Phuttan เอง ทุกฟีเจอร์ของ FAMS เว็บไซต์นี้เอง และโปรเจกต์ใหม่ที่กำลังจะเริ่ม
